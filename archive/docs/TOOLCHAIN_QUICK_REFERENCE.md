# Toolchain Management - Quick Reference

## TL;DR Decision Matrix

| User Type | Recommended Strategy | Why |
|-----------|---------------------|-----|
| **End User** (no dev tools) | `auto` (bundled fallback) | Zero setup, just works |
| **Developer** (has Bun + Rust) | `auto` (system preferred) | Fast, uses existing tools |
| **Corporate** (approved versions) | `system` (strict) | Security compliance |
| **Production** (deployment) | `bundled` | Consistent, isolated |
| **Mixed** (has Rust, no Bun) | `hybrid` | Flexible per-tool |

---

## Quick Configuration Examples

### Example 1: Zero Dependencies (Recommended Default)
```toml
[toolchain]
strategy = "auto"
```
**Result**: Uses system tools if available, bundled if not. Just works everywhere.

---

### Example 2: Developer with Existing Tools
```toml
[toolchain]
strategy = "system"

[toolchain.bun]
min_version = "1.2.0"

[toolchain.rust]
min_version = "1.75.0"
```
**Result**: Fast builds using system tools. Fails with helpful error if not installed.

---

### Example 3: Production/Isolated Build
```toml
[toolchain]
strategy = "bundled"

[toolchain.bundled]
global_cache = true  # Share across projects
verify_checksums = true
```
**Result**: Completely self-contained. Extracts to `~/.forgedb/toolchains/` once.

---

### Example 4: Mixed Environment
```toml
[toolchain]
strategy = "hybrid"

[toolchain.bun]
mode = "bundled"  # Always use bundled Bun (version consistency)

[toolchain.rust]
mode = "system"   # Use system Rust (developer has it)
min_version = "1.75.0"
```
**Result**: Best of both worlds.

## Environment Variable Overrides

```bash
# Quick override for testing
FORGEDB_TOOLCHAIN_STRATEGY=bundled forgedb build

# Force system tools (fail if not available)
FORGEDB_TOOLCHAIN_STRATEGY=system forgedb build

# Use custom Bun location
FORGEDB_BUN_PATH=/opt/bun/bin/bun forgedb dev

# Disable bundled toolchains entirely
FORGEDB_NO_BUNDLED=true forgedb build
```

## Recommended Approach

### For NPM Package Distribution
```toml
# Default forgedb.toml (auto-generated by `forgedb init`)
[toolchain]
strategy = "auto"  # Smart defaults

[toolchain.bun]
mode = "auto"
min_version = "1.2.0"

[toolchain.rust]
mode = "auto"
min_version = "1.75.0"

[toolchain.bundled]
global_cache = true  # Share extracted tools
extract_dir = ".forgedb/toolchains"
```

**What gets bundled in NPM package:**
- ✅ Rust CLI binary (2MB)
- ✅ 4x Bun compiled servers (20MB compressed)
- ⚠️ Rust toolchain on-demand (download if needed, ~150MB cached)

**Total NPM package:** ~22MB

## Key Design Principles

1. **Sensible Defaults**: `auto` strategy works for 95% of users
2. **Progressive Enhancement**: Start minimal, download only what's needed
3. **Explicit Control**: Power users can configure exactly what they want
4. **Fast Developer Experience**: System tools always preferred when available
5. **Reliable Production**: Bundled tools guarantee consistency
6. **Clear Errors**: Tell users exactly what's missing and how to fix it

## FAQ

**Q: Why not just require users to install Bun/Rust?**
A: Reduces friction. Many users just want to try ForgeDB, not set up a dev environment.

**Q: Won't bundling everything make the binary huge?**
A: We use smart bundling: Bun embedded (~20MB), Rust downloaded on-demand (~150MB cached globally).

**Q: What if I want to use my own Bun/Rust version?**
A: Set `strategy = "system"` in `forgedb.toml`. ForgeDB will use your tools.

**Q: Can I bundle different versions for different projects?**
A: Yes! Each project can specify versions in `forgedb.toml`. Tools are cached globally and shared.

**Q: How do I save disk space?**
A: Enable `global_cache = true` (default). Tools extracted once to `~/.forgedb/`, shared across projects.

**Q: What about offline environments?**
A: Use `strategy = "bundled"` and set `distribution = "inline"` to embed everything (larger binary).

**Q: How do I verify toolchain integrity?**
A: Set `verify_checksums = true` (default). ForgeDB verifies SHA256 checksums of all tools.
