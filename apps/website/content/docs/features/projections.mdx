---
title: "Column projections"
description: "Declare @projection(name: cols) to generate a narrow <Model>Card struct and reads that materialize only the selected columns, plus a REST ?projection=<name> closed set."
---

Because storage is columnar, ForgeDB can materialize **just the columns you ask for** instead
of the whole record. A model-level `@projection` directive generates a tailored struct plus
narrow read methods that touch only the primary key and the selected columns — never the full
row.

## Declaring a projection

```forge
model Post {
  +id: uuid
  title: string
  slug: string
  body: string
  author: *User

  @projection(card: title, slug)
}
```

This generates a `PostCard` struct (PK + `title` + `slug`) and narrow read methods. Only
scalar and foreign-key fields may be projected — relation (virtual collection) fields are
rejected at compile time.

## Generated narrow reads

The projection reads materialize only the projected columns, and have live and snapshot
(`_at`) forms:

```rust
let card = db.get_post_card(id);          // Option<PostCard> — reads only PK + title + slug
let cards = db.all_post_card();           // Vec<PostCard>

// Snapshot-scoped:
let snap = db.snapshot();
let past = db.read_post_card_at(&snap, id);
```

<Callout type="note" title="One decode path, no drift">
The projection decoder and the full-record `read_at` both delegate to the same generated
per-field decode body — there is no second read path to drift, and full-record output is
unchanged. The projection just decodes fewer columns.
</Callout>

## Projections over REST

A projection is exposed to the REST API as a **generated closed set** — named declared
projections only, never an ad-hoc `?fields=` column list, so the wire never carries a runtime
column list:

```bash
# Get one record, projected:
curl "http://localhost:8080/api/post/<id>?projection=card"

# List, projected:
curl "http://localhost:8080/api/post?projection=card"
```

An unknown projection name is a 400; omitting `?projection` returns the full record. The
TypeScript SDK gets a matching `PostCard` type plus `getPostCard` / `listPostCard`.

## Limits

- **Declared projections only.** No ad-hoc `?fields=` selection — the projected column set is
  a closed, compile-time set per model.
- **Relation fields cannot be projected** (rejected at compile time).
- REST `list` projection shrinks only the **wire** — the server still reads full rows to
  filter and sort, so the column-skip win is on the point-`get` and browser-replica paths (a
  narrow read faults in only the projected columns). See
  [Browser read-replica](/docs/features/browser-replica/) for the fault-in behavior and
  [Point-in-time reads](/docs/features/snapshot-reads/) for the `_at` snapshot forms.
