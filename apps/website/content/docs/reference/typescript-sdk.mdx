title: "TypeScript SDK"
description: "The generated TypeScript SDK — typed CRUD over the REST API, ListResult, per-model Create types, and typed errors, publishable to npm."
---

`forgedb generate typescript` (or `generate all`) emits a `types.ts` SDK that mirrors the
generated REST contract exactly. It provides typed CRUD per model, a typed error, and — so
you can publish it — a `package.json` and `tsconfig.json` alongside it.

## CRUD methods

The SDK exports a single `ForgeDBClient` class with **flat, model-suffixed** methods
(`get<Model>` / `list<Model>` / `create<Model>` / `update<Model>` / `delete<Model>`) — there
is no per-model sub-object. For a model `Post`, faithful to the real REST responses:

| Method | REST call | Returns |
|---|---|---|
| `getPost(id)` | `GET /api/post/{id}` | the record, or `null` on `404` |
| `listPost(options)` | `GET /api/post` | `ListResult<Post>` |
| `createPost(input)` | `POST /api/post` | the new `id` (throws `ForgeDBError` on `409`/`422`) |
| `updatePost(id, record)` | `PUT /api/post/{id}` | `true`, or `false` on `404` |
| `deletePost(id)` | `DELETE /api/post/{id}` | `true`, or `false` on `404` |

```typescript
import { ForgeDBClient } from "./generated/types";
const db = new ForgeDBClient("http://localhost:3000");

const { data, total } = await db.listPost({ limit: 20, sort: "views", order: "desc" });
const id = await db.createPost({ title: "Hello", views: 0 });
const post = await db.getPost(id);       // Post | null
await db.updatePost(id, { ...post!, views: 1 });
await db.deletePost(id);                 // boolean
```

## `ListResult<T>`

`list` returns the paginated envelope, matching the REST list shape:

```typescript
interface ListResult<T> {
  data: T[];
  total: number;   // matches before pagination
  limit: number;
  offset: number;
}
```

`list<Model>(options)` accepts pagination (`limit`/`offset`), `sort` + `order`
(`'asc'|'desc'`), and a per-field `filter` map, mapped onto the REST query parameters (see
[Generated REST API](/docs/reference/rest-api/)).

## Create input types

Each model gets a create-input type that omits the id:

```typescript
type PostCreate = Omit<Post, "id">;
```

`create<Model>` takes `<Model>Create` and returns the server-assigned id (the REST create
responds `{ id }`, not the full record).

## Typed errors

Failures surface as a typed `ForgeDBError` carrying the HTTP status and the parsed body,
so you can branch on `409` (unique / dangling-FK conflict) versus `422` (field constraint):

```typescript
try {
  await posts.create(input);
} catch (e) {
  if (e instanceof ForgeDBError && e.status === 422) {
    // validation failure — inspect e.body
  }
}
```

## Publishable output

`generate typescript`/`generate all` also emits `package.json` and `tsconfig.json` next to
`types.ts`, **only if absent** — regenerating (even with `--force`) never clobbers them, so
your package metadata is safe to edit. The output is strict-`tsc --noEmit` clean and
npm-publishable.

<Callout type="note" title="Honest limits">
Ids are typed `string` uniformly (URL paths are strings — integer-PK callers pass
`String(n)`); `create` returns the id, not the full record; and there is no WebSocket /
subscription client yet — the SDK is REST-only. For realtime, use the raw
[WebSocket routes](/docs/reference/rest-api/).
</Callout>
